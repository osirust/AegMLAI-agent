# Testmini со строгой проверкой API

**Strict-редакция проверена локально: шесть файловых MC в явном `off` и 17 HTTP-stub проверок PASS.** Квитанция — [TESTMINI_STRICT_RESULT.json](../docs/TESTMINI_STRICT_RESULT.json). `M00-API-002` закрыт только для локального контракта: API-ошибка останавливает процесс до нового CSV. Настоящий Qwen не проверен, новый strict ZIP ещё не отправлен. Это не полный конкурсный агент.

Сначала заканчиваем mini; большое ТЗ в текущем этапе не продолжаем. Порядок и история — [TESTMINI_PLAN.md](../docs/TESTMINI_PLAN.md).

## Запуск и файлы

`solution.py` использует только стандартную библиотеку Python. Путь к `task.md` — первый аргумент; без аргумента читается `task.md` в текущей папке. В рабочей копии рядом находятся:

```text
task.md
train.csv
test.csv
data_dictionary.csv
sample_submission.csv
solution.py
```

Target и ID берутся из ролей словаря, ожидаемая схема CSV — из словаря и sample. Не используем последнюю колонку или название публичной задачи для выбора target. Исходные файлы должны сохранять SHA; мини запускается на рабочих копиях.

## API обязателен по умолчанию

Если `TESTMINI_API_MODE` не задан, режим — **`required`**. Для запроса нужны все три переменные: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. Выполняется один короткий Chat Completions запрос без исполнения текста ответа.

- Только `api_probe.status=success` разрешает продолжить создание CSV.
- Любой другой статус — включая отсутствие/частичность настроек, HTTP-ошибку или сбой запроса — даёт `failed_api_gate`, **exit code 1, без нового `submission.csv`**.
- Итог и `api_probe` записываются в `mini_diagnostics.json`/JSONL-диагностику без значений ключей. Старый CSV не считается успехом нового запуска.
- Автоматического перехода в file-only после API-ошибки нет.

Обычный локальный запуск из папки задачи также использует `required`:

```text
python solution.py task.md
```

**На платформе режим не передаём**: обязательный API-порог должен включаться по умолчанию.

## Явный `off` — только локальная проверка файлов

Для локального file-only прогона без API режим задаётся явно, например в Bash внутри существующей WSL:

```bash
TESTMINI_API_MODE=off /home/aegml/venvs/aegml-py312/bin/python solution.py task.md
```

Этот запуск явно помечается `api_probe.status=disabled_for_local_check`, `api_not_checked=true`: **API не проверялся**. Он не является способом пройти платформенную API-проверку. `off` действует только для показанного процесса и не должен быть записан в сдаваемый код как значение по умолчанию.

После успешного API либо в явном локальном `off` мини выдаёт постоянное предсказание: средний target train для регрессии, самую частую метку train для классификации. Признаки не используются. Создаются `submission.csv` и `mini_diagnostics.json` рядом с task.

Требуются непустой CSV с предсказаниями, ожидаемые колонки, исходный порядок всех test ID, отсутствие повторов/потерь и конечные числовые значения. Пустые test/sample отклоняются с кодом 1: файл из одного заголовка и временный CSV не публикуются. Для public ожидаются 22 449 строк регрессии и 41 166 строк классификации. Код 0 в `required` допустим только после успешного API и корректного файлового результата; код 0 в `off` означает лишь готовность формата. Качество ML, библиотеки, tool calling и AutoResearch этим не проверяются.

`api_used=true` означает попытку запроса, а не успешный ответ. Нужно смотреть `api_probe.status=success` и `api_required=true`. Одно имя итогового статуса `completed_format_only` не доказывает API: в локальном `off` оно возможно с явным `api_not_checked=true`.

## Новая проверка и ZIP

В WSL Python 3.12.3 пройдены **17/17 HTTP-stub проверок**: 12 низкоуровневых и пять проверок основной функции. Подтверждены отказы при отсутствии/частичности настроек и неверном режиме; HTTP 401 даёт код 1 без нового CSV; прежний CSV сохраняет байты и mtime; успешный ответ создаёт CSV с кодом 0. `live_api_used=false`, `user_data_used=false`.

Отдельные шесть файловых MC выполнены с явным `TESTMINI_API_MODE=off`: регрессия — 22 449 строк / 3,1458 с, классификация — 41 166 строк / 1,7153 с; переименование полей, неверный порядок ID, пустые test/sample и чистый ZIP — PASS. Все 12 исходных файлов сохранили SHA. Квитанция: `runs/testmini/20261020T142711Z-fbdadbe0/summary.json`. Это проверка файлов, а не реального API. Добавление проверки пустого test не меняло `solution.py` или ZIP; их SHA ниже остаются действительными.

SHA-256 `check_api.py`: `2c4579744fd287193d260f4d33b0e95f9523ad201e8fca95117a740de1ff8008`. Фактически выполненная HTTP-проверка:

Проверенный архив — **`dist/testmini_strict_api.zip`**, **5 305 байт**, метаданные — **`dist/testmini-strict-api-build.json`**. ## Historical v2: не путать с текущим контрактом

У прежнего optional-варианта были пять MC и 13 HTTP-stub PASS на WSL 3.12.3, дополнительно 13/13 на Windows 3.12.14. Ошибка API могла не отменять успешный CSV — именно это меняет M00-API-002.

Исторический ZIP: 5 001 байт, SHA-256 `3681b720a2b2ef2f642814cd6b7aec17ff3f3821e9d9f3a7927ab3e660112667`; исторический код: `c79390b43c03220f09915e815443426c5863c14817bf9806a3f10aa7551e316a`. Квитанции и детали сохранены в плане mini; эти SHA не описывают новую strict-сборку.

На скриншоте владельца от 20.10 в 17:14 показан **score 0** в «Лучшее решение». **10.3 секунды** обозначают «Длительность загрузки», а не доказанное время исполнения/LLM. Приложенный ZIP совпал с v2 по SHA, но архив на сервере независимо не идентифицирован. По [наблюдению](../docs/PLATFORM_OBSERVATION_20261020.json) API остаётся **UNKNOWN**; подпись статуса и ноль не объясняют исход API или причину score. Примеры `B_RMSE=50`/`B_F1=0.6` условные, официальные значения неизвестны.

**Strict-версия ещё не отправлена, live Qwen не подтверждён.** Как платформа отображает exit code 1 и диагностические статусы, не проверено; локальный отказ не гарантирует определённую подпись в её интерфейсе. Любая новая отправка — по отдельной команде владельца с учётом трёх попыток в сутки на команду и сброса в 00:00 МСК. Нулевой score, наличие CSV или успех HTTP-заглушки не заменяют подтверждённый реальный API-ответ. Большое ТЗ в этом этапе не продолжаем.

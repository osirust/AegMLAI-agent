# Testmini: постоянные предсказания и необязательная проверка API

Это отдельная минимальная проверка файлового интерфейса. `solution.py` использует стандартную библиотеку Python: читает словарь и CSV, записывает `submission.csv`, `mini_diagnostics.json` и события JSONL в stdout. Пакеты не требуются. Один короткий API-запрос необязателен и не влияет на предсказания.

Для регрессии всем test-строкам назначается среднее target из train, для классификации — самая частая метка. Признаки не используются. Успешный CSV не доказывает качество модели по признакам, работу ML-библиотек, AutoResearch или готовность конкурсного агента. Нулевой score возможен; официальный baseline неизвестен. По одному score нельзя судить об исправности запуска.

**Локально: пять MC-проверок и 13 проверок HTTP-заглушки PASS; M00.1–M00.3 закрыты только в этой области.** Файловая квитанция — `runs/testmini/20261020T135943Z-d9de6215/summary.json`, указатель — `runs/testmini/latest-result.json`; API-квитанция — `runs/testmini/api-check-result.json`, сводка — `docs/TESTMINI_RESULT.json`. Платформа — `NOT_SUBMITTED`, настоящий Qwen — `API_WAIT`. Подробности — [TESTMINI_PLAN.md](../docs/TESTMINI_PLAN.md). Текущий этап заканчивается mini; большое ТЗ здесь не продолжаем, прежние H-ID сохраняются.

В WSL Python 3.12.3 проверены регрессия (22 449 строк, 3,0592 с), классификация (41 166 строк, 1,7288 с), переименование target/ID с ведущими нулями, отказ при неверном порядке ID с сохранением старого CSV и запуск распакованного ZIP. Все 12 исходных файлов сохранили SHA. API в двух public-запусках — `skipped_not_configured`; HTTP-протокол проверен отдельно на заглушке. Качество ML, AutoResearch, 49 проверок большого ТЗ и официальный образ не проверены.

Проверены в том числе оборванный chunked-ответ, глубокий JSON, сохранение CSV при ошибке API и запрет redirect на другой сервер. ## Ожидаемые файлы

В отдельной рабочей копии задачи:

```text
task.md
train.csv
test.csv
data_dictionary.csv
sample_submission.csv
solution.py
```

Использовать копии. Не запускать мини непосредственно в каталоге оригинальной выгрузки: результат должен появляться в рабочей папке, исходные файлы должны сохранять SHA.

Target и ID берутся из ролей `data_dictionary.csv`, схема ответа — из словаря и `sample_submission.csv`. Позиция target не фиксирована: у публичной регрессии последним в train стоит `id`. Мини не использует название публичного датасета для выбора target.

## Необязательный API-запрос

- Если `OPENAI_API_KEY`, `OPENAI_BASE_URL` и `OPENAI_MODEL` не заданы, `api_probe.status=skipped_not_configured`; сетевого вызова нет.
- Если заданы все три настройки, выполняется один короткий Chat Completions запрос. Текст ответа не исполняется и не меняет постоянные предсказания.
- Частичные настройки дают `configuration_error`, HTTP-ошибка — `http_error`, другой сбой запроса — `request_failed`. Эти исходы отражаются отдельно в `api_probe`; готовый CSV сохраняется. Локальные HTTP-сценарии проверены на синтетических фикстурах.
- Значения ключей не выводятся в отчёт и не попадают в ZIP. HTTP-заглушка проверяет локальный протокол, а не доступность или поведение настоящего Qwen.

Код выхода **0** и событие `completed_format_only` означают только готовность проверенного CSV и диагностического отчёта. Они не подтверждают успех API. Ошибка основной файловой проверки даёт код **1** и событие `failed`.

## Что проверить после запуска

- `submission.csv` находится рядом с соответствующим `task.md`, содержит ожидаемые колонки в требуемом порядке и не содержит дополнительного индекса.
- Число строк и последовательность ID совпадают с test и sample: 22 449 строк для публичной регрессии, 41 166 для классификации. ID не потеряны и не продублированы.
- Числовые предсказания конечны; категориальный результат — допустимая метка target. Режим среднего или частой метки явно записан в диагностике.
- Сохранены команда, cwd, exit code, stdout/stderr, `mini_diagnostics.json` и SHA результата. Исходные task и CSV не изменились.
- В диагностике отдельно проверены `api_probe`, `features_used=false`, `quality_assessed=false` и `autoresearch_performed=false`; сообщение об успехе формата не подменяет статус API.
- Ошибка входа не объявлена успешным запуском. Наличие диагностического JSON или одного CSV само по себе не является приёмкой всего агента.

Основные события stdout: `started` → `inputs_loaded` → `constant_baseline_fitted` → `submission_validated` → `completed_format_only`. Между ними есть отдельное событие `api_probe`. Любое изменение кода требует новой проверки и связи результата с его SHA.

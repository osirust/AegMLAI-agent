## Что действительно сделано

- `testmini/solution.py`: stdlib, чтение task/CSV/словаря, target/id по ролям, mean для регрессии и majority для классификации; признаки не используются. Рядом с task создаются submission.csv и mini_diagnostics.json, stdout JSONL. Результат проверяется и заменяется атомарно.
- Strict API gate v3: по умолчанию required, один короткий запрос перед CSV. Любое состояние кроме success (включая отсутствие ключа) даёт failed_api_gate/exit1, новый CSV не создаётся, старый не меняется. Явный TESTMINI_API_MODE=off только для локального файлового контроля, API_NOT_CHECKED. Ответ модели не исполняется и не влияет на прогноз.
- Актуальный ZIP `dist/testmini_strict_api.zip`, только solution.py в корне. Старый dist/testmini.zip сохранён как v2/historical. Размер и точные SHA — TESTMINI_STRICT_RESULT. Датасеты, ключи, пакеты и веса в ZIP отсутствуют.
- Проверено в отдельной WSL AegML-Hackathon, Python 3.12.3: для strict v3 повторены оба CSV с явным off; времена/строки/SHA в TESTMINI_STRICT_RESULT. Это файловые тесты, не liveAPI. Шесть файловых сценариев PASS: обе задачи, новые имена полей, неверный порядок ID, пустой test и ZIP. Пустой вход даёт ошибку без публикации CSV только с заголовком; прежний CSV при ошибках сохраняется. 12 исходных файлов не изменились.
- Прямые локальные API-проверки выполнены только на HTTP stub: корректный ответ, ошибки/redirect/оборванный и некорректный ответ; ключей организаторов и расходов не было. Отдельная квитанция сохраняет число и scope тестов. Это не live Qwen.

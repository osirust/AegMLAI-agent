## Ключевые решения

- P0: один Qwen controller, детерминированные supervisor/evaluator, один worker-кандидат. Три роли одной Qwen предусмотрены; независимые контексты E — после сравнения.
- В исследовательской фазе worker получает T_fit с target; y_inner и outer закрыты. Для регрессии: fit 1–3, inner 4, outer 5.
- Основное outer-сравнение оценивает frozen refit на всём development: регрессия 1–4 → outer 5, классификация — аналогично.
- После freeze кода, модели, параметров, preprocessing-рецепта и числа итераций y_inner доступен только refit-фазе в OS-границе; без нового HPO, LLM-правок и feedback.
- Outer target остаётся закрыт всегда. Для primary нужен `refit_performed=true`; no-refit/fallback — отдельный статус и абляция, не primary PASS.
- Основной public F1 — task-вызов с `labels=None`; fixed-10 — только диагностика. Официальные B неизвестны; 50 / 0,60 были условным примером.

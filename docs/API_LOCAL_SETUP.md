**Статус:** `CONFIGURED_UNVERIFIED_NO_LIVE_REQUESTS`. Владелец получил ключ и разрешил настройку локальной конфигурации параллельно H02.2. Root сохраняет секрет; этот документ и агент, который его подготовил, ключа не содержат. Реальный запрос допускается только после отдельной команды владельца «протестить по API».

**Фактическая готовность конфигурации:** `LOCAL_CONFIG_WRITTEN_AND_PERMISSIONS_CHECKED`. Root согласовал приведённые ниже путь, права и flat JSON-поля; запись и права проверены root, [квитанция](LOCAL_PROVIDER_RECEIPT.json). Проверки настройки используют только canary fake. Реальных HTTP-запросов к провайдеру: 0. Авторизация и capabilities остаются непроверенными; live только по новой команде владельца.

Это подготовка подключения. Она не закрывает H06, tool calling, AutoResearch, качество модели или платформенную совместимость. Ни curl, ни HTTP/SDK-запросы при подготовке документа не выполнялись; пакеты и настройки среды этим агентом не устанавливались и не менялись.

## 1. Публичные параметры

Инструкция позволяет читать `OPENAI_MODEL` и сообщает, что прокси подставляет модель задачи независимо от переданного имени. Для локальной явной настройки ожидаемое значение остаётся `qwen/qwen3.8-27b`; это не разрешение другого провайдера и не подтверждение реальной модели по ответу API.

## 2. Приватное хранение вне репозитория

Согласованный путь внутри AegML-Hackathon — `/home/aegml/.config/aegml/provider.json`. Проверенный владелец файла — Linux-пользователь `aegml`; каталог — mode `0700`, файл — `0600`. Запись и права подтверждены [квитанцией root](LOCAL_PROVIDER_RECEIPT.json), без API-запроса. Права Windows/WSL mounts этим документом не проверялись, поэтому предпочтён Linux home внутри отдельной WSL, а не каталог проекта на `/mnt/e`.

Согласованная схема flat JSON использует три строковых поля: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. Секрет записывает только root в приватный файл; значения адреса и модели берутся из таблицы выше. Здесь нет JSON с ключом, действующего `.env`, команды с секретом или копии приватного файла. Будущий загрузчик сопоставляет эти поля с одноимёнными env; фактическую запись подтверждает квитанция root без значений секрета.

Файл не включается в Git, ZIP, исходные task/data, runs, transcript или публичные отчёты. Не выводить его через `cat`, `Get-Content`, shell trace, диагностический env dump или исключение с телом запроса. Для быстрой работы процесс читает секрет непосредственно из private JSON и передаёт его клиенту через env текущего дочернего процесса; ручное включение ключа в командную строку и shell history не требуется.

Подготовленный файл ещё не доказывает корректность ключа, права доступа, доступность endpoint или применённые настройки. Финальный статус и фактическую схему сохраняет root после своей проверки конфигурации; эта проверка может оставаться полностью без сетевых запросов.

## 3. Быстрое использование после отдельного разрешения

1. До команды «протестить по API» ограничиться хранением и проверкой структуры/прав private config без чтения секрета в отчёт. Сохранить статус `CONFIGURED_NO_LIVE_REQUESTS` только по квитанции root, а не по этому плану.
2. После отдельного разрешения использовать существующую ML-venv `/home/aegml/venvs/aegml-ml-py312` в AegML-Hackathon. Одним временным процессом прочитать private JSON, сопоставить три поля с env и создать разрешённый SDK-клиент. Не устанавливать пакеты и не менять глобальную среду.
3. Для первого разрешённого запроса использовать короткое общедоступное сообщение без строк датасета, target, личных данных и секретов. Зафиксировать отдельную цель, предел времени/выхода и число запросов; не включать автоматически инструменты, generated code, fit или повторную серию.
4. Сохранить обезличенный исход: время, имя настройки endpoint/model, HTTP/SDK-статус, длительность и безопасные поля ответа. Не сохранять ключ, Authorization, полный env или необработанное тело ошибки с возможными секретами. Не переименовывать connectivity PASS в tools/research PASS.
5. При отказе сохранить отдельную ошибку и остановиться в пределах разрешённой проверки; не подменять endpoint/провайдера и не запускать скрытые повторные запросы. Дальнейшие capabilities и H06 требуют собственной приёмки.

Точные команды первого live-запроса и его результат в этом документе отсутствуют: владелец ещё не дал требуемую команду проверки. Сетевой доступ через WSL-прокси, сертификаты, авторизация и смысл необязательных параметров не проверены.

## 4. Границы подготовки

Получение ключа, наличие private config, connectivity, native tools, безопасный исполненный инструмент, generated ML-код и AutoResearch — разные результаты. Денежные лимиты не используются для распределения текущей работы по указанию владельца; условия источника сохранены отдельно в приёмке инструкции.

Дата: 20.10.2026. **Локально подтверждены пять MC-проверок и 13 проверок HTTP-заглушки: PASS.** M00.1–M00.3 закрыты только в этой области и для проверенного ZIP. Платформа — `NOT_SUBMITTED`, настоящий Qwen — `API_WAIT`. Код — `testmini/solution.py`; инструкция — [testmini/README.md](../testmini/README.md).

По последнему решению владельца **текущий этап заканчивается лёгкой mini; большое [ТЗ](TECHNICAL_SPEC.md) здесь не продолжаем**. Дальнейшая работа — по отдельной команде. M00 идёт перед H01.1; существующие H00–H12 не переименовываются, мини-этап не закрывает их приёмку.

## Цель и честная граница результата

Testmini проверяет узкий путь: запуск Python → чтение файлов задачи → определение target и ID по словарю → создание корректного `submission.csv` → диагностика. Он использует только стандартную библиотеку Python и не требует ML-пакетов. API-запрос необязателен и не участвует в расчёте предсказаний.

Для числового target предполагается одно среднее значение train для всех test-строк; для категориального — самая частая метка train. Признаки не используются. Это простой ориентир для проверки файлового интерфейса: он не доказывает качество модели по признакам, работу ML-библиотек, AutoResearch, исполнение LLM-кода или готовность полноценного агента.

Нулевой score возможен; официальный baseline неизвестен, поэтому заранее предсказать score нельзя. Сам по себе ноль не объясняет, исправен ли запуск: отдельно проверяем принятие архива, завершение процесса и CSV. Формальная допустимость mini без полноценного решения задачи агентом на платформе пока не подтверждена; необязательный API-запрос этого не меняет.

## Минимальный контракт

- Точка входа — `solution.py`. Путь к `task.md` передаётся первым аргументом; без аргумента ожидается `task.md` в рабочей папке. Это локальный интерфейс testmini, а не подтверждённая точная команда платформы.
- В папке задачи ожидаются `train.csv`, `test.csv`, `data_dictionary.csv` и `sample_submission.csv`. Местные пути `participants` из текста исходных task не считаем существующими автоматически.
- Target и ID определяются по ролям в `data_dictionary.csv`, а не по последней колонке или имени публичной задачи. Схема результата сверяется со словарём и sample.
- Результат — CSV в UTF-8 с запятой, ровно ожидаемые колонки и одна строка на каждый test ID в исходном порядке. ID не должны теряться, повторяться или переставляться. Числовые предсказания конечны, строковые метки соответствуют выбранному категориальному target.
- Рядом с `task.md` создаются `submission.csv` и `mini_diagnostics.json`. Stdout — JSONL с событиями `started`, `inputs_loaded`, `constant_baseline_fitted`, `submission_validated`, `completed_format_only`; возможны дополнительные события API-проверки. При ошибке файлового пути или контракта записывается событие `failed`.
- Код выхода 0 и `completed_format_only` означают только готовность проверенного CSV и отчёта. Код 1 означает ошибку основной файловой проверки. Ошибка необязательного API-запроса отражается отдельно и не отменяет готовый CSV.
- Диагностика явно показывает среднее/частую метку, количества строк, путь результата и `api_probe`. Признаки не используются, качество не оценивается, AutoResearch не выполняется: `features_used=false`, `quality_assessed=false`, `autoresearch_performed=false`.
- Исходные task, словарь, train, test и sample неизменны. Запуски разрешаются только на отдельных рабочих копиях. Невалидный вход должен давать явную ошибку, без ложного сообщения об успехе.

### Необязательный `api_probe`

| Настройки и результат | Поведение |
| --- | --- |
| Нет настроек API | Явный `skipped_not_configured`, сетевого запроса нет |
| Есть все `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` | Один короткий Chat Completions запрос; ответ не исполняется и не используется в предсказаниях |
| Настройки заполнены частично | `configuration_error` в `api_probe`; её нельзя выдавать за успешный запрос или обычный пропуск |
| HTTP-ошибка или другой сбой запроса | Отдельный `http_error` или `request_failed` в `api_probe`; готовый CSV сохраняется, код 0 по-прежнему означает только готовность формата |

Значения ключей не выводятся в диагностику и не включаются в архив. Даже успешный ответ API не подтверждает tool calling, качество ML или AutoResearch. HTTP-заглушка проверяет только локальный протокол; настоящий Qwen требует отдельного live-результата.

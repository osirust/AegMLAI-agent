## M00-API-002: исправление цели mini

**Статус: CLOSED только для локального strict-контракта.** Видимый результат strict-посылки на платформе получен; подробности runtime и прямое подтверждение live API остаются отдельными открытыми вопросами.

- **Факт:** прежняя v2 могла завершаться с кодом 0 и готовым CSV после ошибки необязательного API-запроса. Такой успех подтверждал только формат, хотя цель владельца — проверить API.
- **Действие:** по умолчанию включён `TESTMINI_API_MODE=required`; API проверяется до создания нового CSV. Любой `api_probe.status`, кроме `success`, даёт отчёт `failed_api_gate`, код выхода 1 и отсутствие нового CSV.
- **Закрытие:** на SHA текущего кода воспроизведены успех и отказы обязательного API-порога, явный локальный `off`, сохранность файлов и запуск чистого strict ZIP. По умолчанию используется `required`; результаты сохранены в `TESTMINI_STRICT_RESULT.json`. HTTP-заглушка закрывает только локальную логику, настоящий Qwen требует отдельного live-результата.

Это исправление mini, а не реализация полного конкурсного агента.

## Контракт текущей strict-редакции

`solution.py` использует стандартную библиотеку Python. Путь к `task.md` передаётся первым аргументом; без аргумента ожидается `task.md` в текущей рабочей папке. Точная команда официальной платформы ещё неизвестна.

В папке задачи ожидаются `train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv`. Target и ID определяются по ролям словаря, схема результата сверяется со словарём и sample. Позиция target и публичное название датасета не должны определять поведение.

### Обязательный API-порог

| Режим и исход | Требуемое поведение |
| --- | --- |
| `TESTMINI_API_MODE` не передан | Используется `required` |
| `required`, `api_probe.status=success` | Разрешено продолжить файловую часть; код 0 допустим только после корректного CSV и диагностического отчёта |
| `required`, нет или не хватает `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` | Отчёт `failed_api_gate`, код 1, новый CSV не создаётся |
| `required`, HTTP-ошибка, сбой запроса или любой другой статус кроме `success` | Отчёт `failed_api_gate`, код 1, новый CSV не создаётся; автоматического перехода к file-only нет |
| Явный `TESTMINI_API_MODE=off` | Только локальный file-only прогон; `api_probe.status=disabled_for_local_check`, `api_not_checked=true`. Код 0 не подтверждает API |

На платформе переменную режима **не передаём**: действует обязательный `required`. `off` нельзя использовать как скрытый запасной вариант при ошибке API. Настройки и результат API отражаются в диагностике без значений ключей.

API-проверка — один короткий Chat Completions запрос. Текст ответа не исполняется, инструменты по нему не вызываются, предсказания от него не зависят. Ошибка API должна остановить процесс **до создания нового `submission.csv`**. Наличие старого CSV не является успехом нового запуска.

`api_used=true` означает попытку запроса, а не успешный ответ: успех проверяется по `api_probe.status=success`. Итоговое `completed_format_only` само по себе также недостаточно: в режиме `off` оно возможно при явном `api_not_checked=true`. В локальном `required` API-отказ даёт код 1; как платформа отображает этот код в интерфейсе, ещё не проверено.

### Файловая часть после успешного API или в явном локальном `off`

Для числового target всем test-строкам назначается среднее target из train, для категориального — самая частая метка. Признаки не используются. Это не проверка качества ML по признакам, ML-библиотек, AutoResearch или полного агента.

Результат — непустой `submission.csv` в UTF-8 с запятой: ожидаемые колонки и хотя бы одна строка предсказаний, одна строка на каждый test ID в исходном порядке, без повторов и потерь; числовые предсказания конечны. Пустые test/sample отклоняются с кодом 1, без CSV из одного заголовка и без оставшегося временного файла. Рядом создаётся `mini_diagnostics.json`, stdout содержит JSONL-события. Ошибка файловой части также должна давать ненулевой код.

Исходные task, словарь, train, test и sample неизменны; проверяем только рабочие копии. В публичной регрессии последним в train идёт `id`, target расположен перед ним. Ожидаются 22 449 строк результата для регрессии и 41 166 для классификации.

## M00.4: наблюдение strict-посылки на платформе

Источник — [PLATFORM_STRICT_OBSERVATION_20261020.json](PLATFORM_STRICT_OBSERVATION_20261020.json), скриншот владельца от 20.10. На нём показаны `testmini_strict_api.zip`, время загрузки **17:32**, **score 0** и статус **«Лучшее решение»**. **3.2 секунды** находятся в колонке **«Длительность загрузки»**; это не доказанное время работы агента или API-запроса.

ZIP из Downloads побайтово совпал с нашим strict-архивом: 5 305 байт, SHA-256 `c9ffb571136205495cbef5b2da44b3712f85f1d289ac2c343f44108e1f3b908f`, код `81908e49c2eb00f81659cea825371043ec03b991a8bbb446cb8ff05ff75813e9`. Серверный SHA независимо не получен.

Это **положительное свидетельство видимого результата strict-посылки**. Если платформа выполнила этот код в режиме `required` по умолчанию и отображаемый статус означает нормальное завершение с кодом 0, из контракта следует успешный API-ответ и создание непустого проверенного CSV. Статус вывода — **`API_SUCCESS_INFERRED / NOT_DIRECTLY_VERIFIED`**, а не безусловный live PASS.

Фактические exit code, env и `mini_diagnostics.json` платформы неизвестны; семантика её подписи статуса напрямую не проверена. Поэтому M00.4 — `SUBMISSION_OBSERVED / DETAILS_PENDING`; локальный ключ остаётся `API_WAIT`, удалённый API имеет условный вывод выше. Score 0 не превращается в оценку качества ML и не объясняет причину результата.

## Что пока не закрыто

Отправка strict-версии наблюдается по свидетельству владельца; прямые детали выполнения ещё не получены. На платформе три попытки в сутки на всю команду, сброс в 00:00 МСК; остаток командной квоты и возврат ошибочной попытки не подтверждены. Новая отправка — только по отдельной команде владельца.

Успех синтетического HTTP не подтверждает настоящий Qwen. Для strict-посылки есть условный вывод об успехе удалённого API, но нет прямой runtime-квитанции; даже реальный API-ответ не проверяет tool calling, AutoResearch, качество ML и 49 сценариев большого ТЗ. Локальная коррекция M00-API-002 завершена; большой план в этом этапе не продолжаем.

# Команда: независимые версии и общий выбор

Актуальное решение владельца от 19–20.10.2026: четыре участника первые три дня создают независимые версии агента, затем выбирают лучшую и отдельно улучшают выбранный код. Прежнее распределение четырёх модулей больше не является рабочим планом.

В этом чате разрабатываем **версию Владимира вместе с Codex на его ПК**. Другим участникам автоматически не назначаем задачи и не отправляем сообщения; их фактическую доступность не предполагаем. Полное ТЗ находится в [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md).

## Что согласовать для сравнения

1. Использовать одинаковые SHA источников, входные задачи, формат ZIP и критерии корректного CSV.
2. Зафиксировать одинаковые ограничения времени, CPU и RAM, а также общий протокол разбиения: временной для регрессии и стратифицированный для классификации. Это предложение владельца; согласие других участников пока не получено.
3. Не складывать RMSE и F1 напрямую. Показывать обе метрики, время, корректность результата, пиковую память и отказы. Вспомогательный балл возможен только относительно заранее зафиксированной общей отправной точки и с явным пояснением; он не заменяет официальный score.
4. Сохранять результаты всех одинаковых проверок, включая неуспешные. Интерфейс, число агентов и один удачный прогон не являются достаточным основанием для выбора.
5. Не передавать независимый контроль в промпты и подбор решения. Даже выбранный по одному outer-сравнению победитель имеет selection bias; для независимой оценки именно победителя нужен новый резерв/private. Если по раскрытым результатам контроля повторно подбирались решения, эта выборка становится частью разработки и больше не служит независимым доказательством.

## После выбора

Зафиксировать выбранный commit, ZIP, SHA и таблицу результатов. Вносить изменения в отдельных ветках небольшими проверяемыми шагами, сохраняя исходную рабочую версию. Для каждого изменения записывать цель, фактическую реализацию, команду и результат проверки, оставшиеся ограничения.

Внутри нашей версии этапы H01–H12 выполняются строго последовательно по команде владельца. Обзор источников и проектирование H01 подготовлены; экспериментальное сравнение ещё не выполнялось. Следующий кодовый подпункт после ТЗ — H02.1, только по соответствующей команде. Сначала регрессия и классификация должны заработать через общий контракт, затем нужно доказать AutoResearch и перенос на новые задачи. Несколько ролей одной Qwen исследуются как гипотеза и сами по себе не гарантируют улучшения.

Платформа оценивает решение на CPU: 8 CPU и 32 GB RAM, до трёх часов от начала процесса на задачу. Наличие GPU на нашем ПК не заменяет проверку в этих условиях. По ответу организаторов от 20.10 в 00:14 запись доступна в рабочую папку и `/tmp`, место — ориентировочно 30–35 GB, отдельного лимита числа файлов нет; точная команда запуска остаётся неизвестной.

По указанию владельца бюджет 600 ₽ в рабочем планировании не учитываем. Репозиторий уже private, что подтверждено повторным API GET после PATCH. Исходные материалы и данные пока в Git не добавлены; конкретный выбор файлов для возможной загрузки рассматривается отдельно. Ключи, `.venv`, веса и `runs` не публикуются. ZIP для оценки не включает данные.

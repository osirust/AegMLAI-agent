Проверено:

- Обе реальные задачи читаются одним builder без ручного указания публичных target: регрессия — 62 признака, строки train/test/sample `53308/22449/22449`; классификация — 42 признака, `87670/41166/41166`. Исходные пять файлов каждой задачи сохранили SHA. Извлечены RMSE/minimize и MacroF1/maximize; метрики ещё не вычислялись.
- Объявленный вложенный путь имеет приоритет. Если указанный nested-файл отсутствует, единственный корневой файл разрешается с записанным `flat_fallback`. Два подходящих кандидата без однозначного основания вызывают отказ. Проверены URI, абсолютные входные ссылки, обход `..` и внешние symlink. Symlink самого task привязывается к физическому каталогу task; входы после разрешения остаются внутри него. Это проверка resolver, не OS-песочница.
- Target не зависит от позиции. Числовые метки при явно заданной классификации остаются классификацией. Противоречивые target/type/metric, неизвестная основная метрика, неоднозначные файлы и неверная схема отклоняются до дорогой работы. Пропуски признаков не удаляют строки и не заполняются этой стадией.
- ID сравниваются как исходные строки: `001`, `1` и `NA` различаются. Проверены duplicate/blank/mismatch, допустимое пересечение train/test ID, переставленные sample ID и обе направленные карты. Порядок результата задаёт task; для обоих public это **test**, а sample задаёт формат колонок. При отсутствии явного порядка различные test/sample последовательности неоднозначны. Позиционное сопоставление допускается только по явному правилу, включая sample-only ID.
- Перестановка признаков test сохраняет явную проекцию к порядку train; перестановка колонок sample не приводит к навязанному префиксу ID. Placeholder target в sample не используется как правильный ответ.
- Встроенные Draft 2020-12 схемы валидируют finite JSON и согласованность TaskContract/MetricContract. Нет статического JSON-asset, MCP, SDK или runtime pip. Защищённые копии контракта не меняют авторитетные mappings.
- Выборочное копирование только четырёх корневых `.py` и исходного requirements позволяет выполнить точный CLI `python3 solution.py task.md` в чистом каталоге. Создаются только свежие `.aegml_runs/<UUID>/task_contract.json` и `row_alignment.json`, с SHA и безопасной публикацией. Исходные файлы и существующий CSV сохраняются. Невалидный run ID отклоняется до файловой записи.
- Кооперативное истечение того же бюджета даёт 124; неверный контракт — 2. Нормальный H02.3 даёт **exit 3 / implementation_incomplete**, `contract_valid=true`; API/tools/research/submission false, experiments 0. Этот код ещё не готов для конкурсной отправки.

Поддержан один supervised target и ограниченная явная RU/EN-грамматика, а не произвольное понимание любого текста. Реестр содержит схемы восьми метрик (RMSE, MAE, accuracy, macro/weighted/binary F1, log loss, ROC AUC); наличие схемы не означает готовность вычислителя или проверку всех вариантов метрики. Неподдержанная постановка завершается явным отказом.

Лимиты parser — task 1 MiB, dictionary 4 MiB, каждый CSV 1 GiB, до 2 млн строк, 4096 колонок, 100000 entries обхода; длина физической CSV-строки до 4 Mi символов, ID до 4096 символов, сохраняемый текст ключей до 128 Mi символов. Это защитные пределы реализации, не замер peak RAM или доказательство соблюдения 32 GB на всех данных.

## Где выполнять код

1. **Windows/Codex:** редактирование и Git. Исходная копия кейса остаётся в `E:/work/AegMLAI-agent/drive-download-20261019T181414Z-1-001`.
2. **WSL2 / AegML-Hackathon:** отдельная Linux-среда на E: с venv Python 3.12. Рабочую копию кода, временные файлы и кеши храним внутри Linux filesystem, например `/home/aegml/projects/AegMLAI-agent`, а не обучаемся поверх `/mnt/e`. Пока каталог `projects` подготовлен, код и данные туда не копировались. Согласование будущей копии — явно по commit/SHA; не создавать два расходящихся «главных» репозитория. Это соответствует [рекомендации Microsoft о файловой системе](https://learn.microsoft.com/en-us/windows/wsl/filesystems).
3. **Docker с Linux backend:** финальная проверка чистой распаковки ZIP, ресурсов, путей и отказов. Нужен официальный образ/его описание. Просто Ubuntu или Docker без этого образа не доказывает полную совместимость. Вариант Docker Desktop на WSL2 описан в [официальной документации](https://docs.docker.com/desktop/features/wsl/); выбор конкретной установки делается после проверки уже имеющейся Linux-среды.

Это всё вычисления на том же компьютере, WSL не является внешним сервером. GPU не обязателен и не включается в конкурсную проверку. Одновременно тренируется один кандидат; суммарные threads всех процессов ограничиваются выделенными CPU.

## Память

По [документации WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config) стандартный предел VM — 50% памяти Windows. Фактически новая среда видит около 15,18 GiB; свободную RAM/swap и нагрузку измерим перед тренировками. Виртуальная ёмкость VHD не равна свободному месту физического E:.

Предложение для локальной разработки: до 8 логических CPU и около 20–24 GiB RAM при достаточной свободной памяти Windows, с проверкой реального RSS. Это предложение, настройки ещё не менялись. Полную платформенную память 32 GB на хосте с 32 GiB и работающей Windows честно воспроизвести нельзя. Более строгий локальный прогон полезен, но не равен проверке официального лимита. Глобальный `.wslconfig` влияет на все дистрибутивы; не менять и не выполнять `wsl --shutdown` в рамках подготовки документов.

## Что скачивать первым в H02

Этот раздел — будущая настройка по H02.1, не выполненная установка. До обращения к сети проверить версии в отдельной среде; pip пока отсутствует. Затем получать **Linux wheels под Python 3.12**, без изменения глобального Python. Минимум из выданных pins:

```text
numpy==1.26.4
scipy==1.12.0
pandas==2.2.3
scikit-learn==1.5.2
catboost==1.2.8
joblib==1.4.2
threadpoolctl==3.6.0
openai==1.68.2
httpx==0.28.1
pydantic==2.10.6
psutil==6.1.1
```

Загрузчик также разрешит необходимые транзитивные зависимости; их версии и источники фиксируются, установка проверяется. Это стартовый набор для нашей реализации, **не замена официального requirements** и не утверждение о полной воспроизводимости образа. Полный список содержит 37 pins; прямого конфликта между явно закреплёнными версиями при чтении PyPI metadata не найдено, полный resolver/native import ещё не проверен.

После появления работающего baseline добавлять LightGBM/XGBoost и один выбранный AutoML-движок для H09. Torch, GPU/CUDA-компоненты и все три AutoML-фреймворка сразу не обязательны. Не скачивать веса Qwen, pretrained embeddings или внешние датасеты; MCP устанавливать для нашей архитектуры не требуется.

Скачивание пакетов/получение согласованного образа можно выполнять параллельно с написанием кода, но обучение и замеры сравнения — последовательно, чтобы ресурсы и время были сопоставимы. Факт успешного download не равен успешной установке, импорту или обучению. В оценочном контейнере установка и произвольная сеть отсутствуют.

## Приёмка H02 для среды

Зафиксированы Linux/Python версии, абсолютные пути рабочей копии/окружения/кеша, commit и data SHA; пакеты установлены только в отдельную среду, импорты нужного подмножества проходят. Конкурсный entrypoint стартует без MCP, исходники кейса неизменны. Память/CPU и готовность Docker измерены отдельно; отсутствие официального образа остаётся HOLD, а не выдаётся за PASS.

## Вход в уже созданную минимальную среду

В PowerShell:

```powershell
wsl -d AegML-Hackathon --cd /home/aegml
```

В открывшемся Linux-shell:

```bash
source /home/aegml/venvs/aegml-py312/bin/activate
python --version
```

Сейчас это только stdlib-окружение. WSL сообщает о Windows localhost-прокси, не отражённом в NAT. Сеть из Linux ещё не проверялась; глобальную сетевую конфигурацию не меняли. Перед будущим получением пакетов этот пункт отдельно проверяется. Venv и отдельная WSL не являются песочницей для произвольного сгенерированного кода.

# Контракт backend и запуска AegML

Редакция: 20.10.2026. Статус: проектный контракт; полноценный конкурсный агент ещё не реализован.
**Проект уточнения для следующего обсуждения большого ТЗ.** Mini закончена отдельно; этот документ не означает реализацию полного backend.

Основание: [основное ТЗ](TECHNICAL_SPEC.md), [состояние проекта](../PROJECT_STATE.md), полученные task/baseline/PDF и ответ организаторов 20.10.
Этот документ не запускает реализацию, установки, обучение или обращения к API.

## 1. Что является продуктом

Обязательный backend — **автономное CLI-приложение на Python 3.12**, а не постоянно работающий HTTP-сервис.
В ZIP находятся `solution.py` в корне и собственные импортируемые модули рядом; установка нашего src-layout пакета не требуется.
FastAPI, web frontend, браузер, внешняя БД и пользовательский UI не являются обязательными зависимостями запуска.
Один неизменный архив должен самостоятельно решать отдельные новые задачи, не перенося состояние между ними.
Владельцу сдаётся проверяемый код; платформа получает ZIP и сама запускает вычисления на предоставленных данных.

## 2. Вход, обработка и выход

| Часть | Обязательный контракт |
|---|---|
| Вход | `task.md`, `train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv` для одной задачи |
| Разбор | Определить пути, target/id/features, тип задачи, метрику и направление, допустимые классы и формат ответа |
| Регрессия public | Target `site_eui`, RMSE на исходной шкале, конечное число для каждого test ID |
| Классификация public | Target `attack_cat`, Macro F1, десять строковых классов с `Normal`; вероятности не заменяют метки |
| Выход | `submission.csv` в UTF-8, запятая, без дополнительного индекса; нужные колонки и точный порядок test ID |

Target определяется по условию, ролям словаря и согласованию файлов, а не по последней колонке.
Новые private-имена и метрики разбираются через общий контракт; public-названия не служат переключателем алгоритма.
Противоречия и неподдержанные случаи дают явную диагностику; sample не считается источником правильных ответов.
По ответу организаторов 20.10 код копируют в папку задачи: `solution.py`, `task.md` и итоговый CSV находятся рядом, запуск идёт из неё.
Проект ориентируется на интерфейс baseline `python solution.py <task.md>`; точная команда платформы ещё не подтверждена.
Рабочие артефакты разрешены в cwd, его подкаталогах и `/tmp`; исходные task/CSV/dictionary сохраняются побайтно.
Расхождение реальных плоских путей выгрузки и путей `participants` в task разрешается явно, без выбора случайной копии файла.
Первый валидный CSV сохраняется рано; новые кандидаты заменяют его атомарно только после независимой проверки.
Статус `completed` возможен только при существующем валидном результате; текст LLM без CSV не означает успех.

## 3. Полный агент и диагностический mini — разные уровни

Полный runtime: описание/профиль → гипотеза → код → ограниченный executor → измеренная метрика → keep/revert → следующая гипотеза.
Supervisor и evaluator проверяют результаты независимо от утверждений LLM; split и внешний контроль недоступны для подмены кандидатом.
Нужны реальные подтверждённые итерации и перенос на другие задачи; один вызов `.fit` через LLM этого не доказывает.
Диагностический mini проверяет Python, пути, контракты и CSV; метрику качества не измеряет. Strict mini v3 требуетAPI-success доCSV; запрос не участвует в прогнозе, но его отказ теперь останавливает процесс.
Он может использовать заранее проверенный код/малую фикстуру; это не доказательство live tool calling, AutoResearch или качества полного агента.
Уже созданная stdlib venv проверялась только на версию/prefix и CSV/JSON write-read; ML, агент и контейнер этим не проверены.
Факты, будущие сценарии и результаты не смешиваются: [матрица](TEST_MATRIX.md) остаётся планом до относящихся запусков.

## 4. Три разных слоя локальной работы

| Слой | Назначение и статус |
|---|---|
| Windows / редактор Codex | Редактирование и Git в `E:\work\AegMLAI-agent`; это рабочее место разработчика |
| WSL2 host `AegML-Hackathon` | Linux-исполнение на том же ПК; VHD находится в `E:\WSL\AegML-Hackathon`; создана отдельная stdlib venv Python 3.12.3 |
| Docker Engine в AegML WSL | Планируемый поздний слой проверки образа, чистого ZIP и ограничений; установка и проверка ещё не выполнены |

Рабочую Linux-копию предстоит синхронизировать по commit/source SHA; не создавать два расходящихся главных репозитория.
Venv и отдельный дистрибутив сами по себе не являются защитой от произвольного сгенерированного кода.
Docker не нужен для простого stdlib mini; его устанавливают позднее, после локальной мини-проверки и выбора способа развёртывания.
**Не устанавливать Docker Engine и Docker Desktop одновременно** как два конкурирующих варианта этого проекта.
До финальной готовности обязательны чистая распаковка и контейнерная проверка; если организаторы дают точный образ, проверяется именно он.
Без точного образа результат подписывается как локальное приближение и не закрывает совместимость официальной среды.

## 5. Ресурсы: план локали и отдельный контракт платформы

Согласованный ориентир локали — WSL до **24 GiB**, Docker внутри неё до **20 GiB / 8 CPU**, Windows остаётся около **8 GiB**.
Docker-память входит в WSL-память, а не добавляется к ней. Это **план**, не применённые настройки и не воспроизведение платформенных 32 GB.
Фактически минимальная WSL сейчас видела 12 логических CPU и около **15,18 GiB RAM**; этого может хватить для небольшого теста.
Достаточность устанавливается измерением свободной памяти/пика конкретного запуска, а не предположением о необходимости расширить VM.
Глобальный `.wslconfig` затрагивает все WSL-дистрибутивы, включая работу AEGYX; ради простого mini его не меняем.
Платформа задаёт **8 CPU, 32 GB RAM и не более 3 часов на каждую задачу** от старта процесса.
Wall-clock включает чтение, LLM/ожидания, обучение, ошибки, финальный refit, predict и запись; CSV должен существовать до остановки.
Все потоки/дочерние процессы учитываются суммарно; сначала проверяется CPU-контроль, одновременно тяжёлые кандидаты не обучаются.

## 6. Разрешённый LLM и границы правил

Live использует только выданный для кейса API **Qwen3.8-27B**; ключ, точный endpoint/model ID и поддержка tools ещё ожидают подтверждения.
Имена окружения baseline: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`; они поступают runtime и не записываются в ZIP/логи.
Название `openai` относится к SDK/протоколу интерфейса Qwen, а не к разрешению произвольного поставщика или другой модели OpenAI.
Без проверенного адреса разрешённого endpoint нельзя молча переключаться на стандартный сервер SDK; strict mini требуетполныйнаборнастроек, иначеexit1; при полномнабореодин запрос, локальнопроверен толькоHTTPstub.
Схемы tools, таймауты, ограниченный retry и сетевое исключение проверяются отдельно; успешный mock не закрывает live-HOLD.
GPU локально **не объявлен общим запретом**: возможные ускоренные эксперименты отделяются от обязательной CPU-проверки платформы.
Локальная копия той же Qwen для dev — предложение, допустимость которого требует уточнения; не называем её уже разрешённой или запрещённой.
Базовый план остаётся на выданном API; до уточнения веса не скачиваются и такая замена не включается в конкурсный runtime.
Для обучения ML — только данные кейса и разрешённые версии библиотек, без внешних датасетов и предобученных ML-весов.

## 7. Упаковка и условие готовности

Используется проверенное необходимое подмножество разрешённых pins и их согласованные зависимости; во время оценки нет `pip install` и загрузок.
ZIP содержит код/нужные статические конфиги, но не данные, секреты, venv, сторонние библиотеки, кеши и обученные веса.
Лимит загрузки — **128 MB**; до уточнения единиц консервативный предел — **128 000 000 байт**, размер и SHA записываются.
Доступны три попытки сабмита в сутки на команду; автоматическая загрузка не следует из готовности локального ZIP.
Готовность требует фактов: чистые импорты, обе public-задачи, корректные CSV, fault/resource-проверки, live-цикл и перенос неизменного кода.
Сейчас есть документация и минимальная отдельная среда; полный backend, ML-проверки, Docker, live Qwen и платформенный запуск ещё впереди.

## 5. Принятая методология, ещё не проверенная кодом

- Основной public Macro F1 соответствует task: `labels=None`; fixed-10 считается отдельно как диагностика. Официальные B_RMSE/B_F1 неизвестны; 50 / 0,60 — только пример.
- Исследовательский worker получает T_fit с target; y_inner и outer остаются у evaluator. Early stopping допускается только внутри T_fit.
- Primary outer-сравнение: после freeze кода, модели, гиперпараметров, preprocessing-рецепта и числа итераций выполняется frozen refit на всём development. Для регрессии — 1–4 → outer 5; классификация устроена аналогично.
- y_inner разрешён только этому refit-worker в OS-границе, не LLM. Новых HPO, LLM-правок и feedback после freeze нет; outer target закрыт всегда.
- `refit_performed=true` обязателен для primary. No-refit/fallback хранится отдельным статусом и не считается primary PASS; refit входит в общий wall-clock.

Это контракт будущих запусков. Он не подтверждает отсутствие утечки в ещё не написанном коде, успех refit или перенос на private.

[Машинная квитанция](H022_BOOTSTRAP_RESULT.json), [проверочный скрипт](../scripts/check_h02_bootstrap.py). Сырые локальные результаты: `runs/h02/h022-20261020T165645Z/attempt2/bootstrap.json`.

Проверено:

- Выборочное копирование только `solution.py`, `aegml_contracts.py` и неизменённого `requirements.txt` в чистый каталог. В нём выполнена именно команда `python3 solution.py task.md`, без src-layout, установки нашего пакета, MCP и статических assets.
- Default, absolute и relative task path, другой cwd, кириллица и пробелы. Путь фиксируется относительно запуска, будущий output — рядом с task; cwd не меняется. Содержимое task/CSV пока не интерпретируется.
- Приоритет CLI → разрешённая env → default; нечисловые, NaN/Inf, нулевые, отрицательные и превышающие 10800 секунд бюджеты отклоняются. Проверены резерв и threads от 1 до 8; thread env не является OS-лимитом CPU.
- Один ранний monotonic start до собственного модуля и будущих ML-импортов. Общий frozen budget даёт work/hard deadline, остаток и отказ admission. Повтор не получает новый срок. Резерв входит в общий T: по умолчанию T=10800, reserve=600, work=10200 секунд. Если действие дороже положительного остатка, возвращается отдельный ActionBudgetInsufficient: можно выбрать более короткое действие; BudgetExpired означает именно истечение фазы.
- С управляемыми часами проверены истечение, расход и резерв. В отдельной **инструментированной копии** contracts задержка импорта учитывается, после исчерпания возвращается 124. Она не прерывается посередине сна: это учёт времени, а не hard timeout.
- Missing/partial/complete OPENAI env классифицируются без SDK и сетевого запроса. Canary-ключ, credential URL, модель и неверный CLI не раскрываются в stdout/stderr/repr/outcome.
- Существующий CSV сохраняет содержимое и mtime; SHA исходных файлов не меняются; новый CSV не создаётся. Старый CSV не объявляется текущим валидным результатом.
- Три связанные проверки H02-BOOT-001: expiry, invalid path и invalid threads сохраняют timer snapshot и дают коды 124/2/2. Независимый read-only разбор подтвердил результат на тех же SHA.

После статического ответа чата «2» добавлены четыре точечных проверки: безопасный timer при внутреннем отказе, fallback при сбое snapshot, устойчивый outcome при неисправных часах и отдельная категория недостатка времени для действия.

# Продолжение полноценного проекта

Редакция полного ТЗ прошла содержательную и автоматическую документальную сверку. Обзор источников завершён только в письменной области; код агента и экспериментальное исследование ещё не выполнялись.

Сейчас завершаем полное ТЗ, обзор первичных источников и математический/экспериментальный план. Mini остаётся историей минимального API/CSV-контакта; полного агента, обучения и сравнений ещё нет.

Перед продолжением читать: PROJECT_STATE → READ_FIRST → выбранный H-раздел TECHNICAL_SPEC → WORK_BLOCKS. Доказательства проверять по EVIDENCE_REGISTER и конкретным JSON/SHA. Не перечитывать всё без причины, но относящийся контракт читать полностью.

**Ближайший кодовый подпункт после ТЗ — H02.1, по отдельной команде владельца:** подготовить минимальные разрешённые пакеты в существующей AegML venv, не меняя AEGYX.
Затем H02.2 — entrypoint, H02.3 — TaskContract, H03.1–H03.5 — данные/метрики/CSV, H04.1–H04.4 — реальные модели обеих задач. Всю цепочку автоматически не запускать.
До generated execution обязательны Docker/profile H02.4 и подтверждённая OS-граница H05.1. H07 зависит от H04, H05 и H06.
Без ключа можно готовить offline-протокол H06.1; H06.2 после получения ключа проверяет реальный безопасный инструмент, без generated ML-кода.

`API_WAIT_LOCAL` сохраняется. Ожидание ключа «в течение часа» — ETA, не факт получения; endpoint, model ID и capabilities неизвестны.
Запасные собственные providers не используются. Допустимость локальной той же Qwen — UNKNOWN; веса сейчас не скачиваются. Почта, расписания и платные вызовы автоматически не проверяются.

Сохранить методологию: основной F1 как в task (`labels=None`), fixed-10 отдельно; исследовательский worker не видит y_inner/outer.
Primary: после freeze кода, модели, параметров, preprocessing и числа итераций выполнить frozen refit на полном development, затем outer-оценку.
Для регрессии это 1–4 → outer 5; для классификации — T_fit + inner → outer. y_inner разрешён только refit-фазе в OS-границе, без HPO, LLM-правок и feedback; outer target закрыт всегда.
`refit_performed=true` требуется для primary. No-refit/fallback — отдельный результат, не primary PASS. Время refit входит в общий бюджет.

План содержит 50 H-подпунктов, 15 MATH, 15 HARN и 14 R. Все 74 основных будущих сценария и 17 пересекающихся HARN-T деталей — NOT_RUN; это не 91 независимая проверка.
Прежние 21 demo PASS, 6 MC с explicit off и 17 stub-проверок mini не закрывают полный runtime. OPEN: SPEC-BASE-001..006, SPEC-ADAPT-001..003, SPEC-DATA-001; закрытые CORE/M00/DOC сохраняют свой scope.
Mini-квитанции v2/v3 не переписывать. Strict ZIP — 5 305 байт; source SHA `81908e49c2eb00f81659cea825371043ec03b991a8bbb446cb8ff05ff75813e9`.
Показанные 17:32 / score 0 / «Лучшее решение» / 3,2 с относятся к наблюдению платформы и загрузке. API/CSV — условный вывод, не полученный actual exit 0 и не runtime 3,2 с.

Использовать уже созданную AegML-Hackathon на E:, Python 3.12.3, venv без ML; ранее видны около 15,18 GiB / 12 CPU. WSL 24 GiB / Docker 20 GiB / 8 CPU — только план.
Не переустанавливать минимальную среду; не менять прежнюю Ubuntu/default, AEGYX и общий `.wslconfig`, не выполнять глобальный `wsl --shutdown`.
Ключи, данные, venv, веса, runs и dist не публиковать в Git. Бюджет 600 ₽ не рассчитывать; участники делают независимые версии. Новые сабмиты и сообщения другим чатам/организаторам — только по команде владельца.

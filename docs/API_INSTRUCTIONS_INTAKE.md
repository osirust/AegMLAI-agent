## 2. Правила конкурсного запуска

- Платформа сама подставляет `OPENAI_BASE_URL` и `OPENAI_API_KEY`. Собственные адрес и ключ нельзя фиксировать в сдаваемом коде. Локальные настройки и платформенные env необходимо различать.
- После старта доступен только предоставленный прокси. Обращения к своему хосту, прямому адресу модели и runtime `pip install` не проходят по условиям инструкции.
- Для HTTP/SDK используются библиотеки из предоставленного списка. Зависимости устанавливает платформа из корневого requirements до запуска; собственная установка из скрипта запрещена.
- Подтверждён прежний упаковочный контракт: только корневые `.py` и предоставленный `requirements.txt`, без папок и остальных assets; ZIP до 100 МБ. Команда — `python3 solution.py task.md`; CSV рядом с task. Рабочие подкаталоги и `/tmp` разрешены во время выполнения.
- Ресурсы одного запуска задачи: 8 CPU, 32 ГБ RAM и до трёх часов. Документ не сообщает фактический Docker image/digest или доступность механизмов изоляции worker.

## 4. Бюджет и ошибки

В инструкции указан лимит **600 ₽ в день на один ключ**; все, кто использует этот ключ, расходуют общий остаток. При сообщении `Budget has been exceeded` предписано дождаться сброса в **03:00 МСК**. Конкретный HTTP-код, тело ошибки и механизм учёта токенов не приведены. По решению владельца эти 600 ₽ не используются для распределения текущей работы; здесь сохранён только факт источника. Сброс API-бюджета в 03:00 нельзя смешивать со сбросом командных попыток отправки в 00:00 из другого правила платформы.

Остальные перечисленные ошибки относятся к загрузке и проверке решения: формат, превышение времени, нехватка результата/отсутствующий файл, ошибка скоринга. Это не таблица HTTP-ошибок Qwen API. Очередь Boosters ещё не результат; завершённая успешная проверка обозначается сообщением «Точность вычисления: …». Подробные технические логи могут быть доступны только администраторам.

# Первичные источники для проектирования AegML

Дата проверки ссылок и содержания: **20.10.2026, МСК**. Область — исследование и документация. Этот реестр не является отчётом о локальном benchmark, проверкой разрешённого endpoint или разрешением на установку/обучение. Никакие внешние тренировочные данные, решения соревнований, пакеты и веса для этого чтения не получались.

Главные требования конкурса остаются в исходных `task.md`, PDF и [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md). Реестр поддерживает [исследование AutoML](AUTOML_RESEARCH_BRIEF.md), [протокол сравнения](RESEARCH_PROTOCOL.md), [математику и валидацию](MATHEMATICS_AND_VALIDATION.md), [проектирование Qwen harness](QWEN_HARNESS_DESIGN.md) и будущие H01/H03/H05–H09. Он не меняет правила кейса. Возможности настоящего Qwen API всё ещё требуют своей проверки; наличие документации или `reasoning_content` не доказывает tool calling.

Ниже 15 записей. **Факт источника** означает прочитанное утверждение авторов или определение официального API. **Наше решение** — вывод для проектирования, который ещё предстоит проверить. **Граница переноса** запрещает превращать чужие результаты в обещание качества, скорости или безопасности нашего агента. Все будущие эксперименты по этим решениям — `NOT_RUN`.

## Агентное ML-исследование: ранние работы и оценка

### RSRC-001 — ReAct

**Источник:** Yao et al., [ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629v3). Идентификатор: `arXiv:2210.03629v3`; v1 — 06.10.2022, прочитанная редакция v3 — 10.03.2023. Проверен 20.10.2026: метаданные и авторский abstract.

**Факт источника:** авторы соединяют рассуждение и действия с наблюдениями среды, чтобы обновлять план по ходу задачи. **Наше решение:** журналировать краткую проверяемую гипотезу, действие, настоящий результат инструмента и следующий выбор; текст плана сам по себе не считать экспериментом. **Граница переноса:** работа не устанавливает качество ML-агента на нашем датасете. Концептуальный цикл ReAct не требует буквально копировать stopword-парсер `Thought/Action/Observation` в Qwen или требовать раскрытия внутреннего chain of thought; wire-протокол проверяется отдельно по RSRC-009.

### RSRC-002 — MLAgentBench

**Источник:** Huang, Vora, Liang, Leskovec, [MLAgentBench: Evaluating Language Agents on Machine Learning Experimentation](https://arxiv.org/abs/2310.03302v2). Идентификатор: `arXiv:2310.03302v2`; v1 — 05.10.2023, v2 — 14.04.2024. Проверен 20.10.2026: метаданные и abstract.

**Факт источника:** benchmark рассматривает ML-экспериментирование через чтение/изменение файлов, выполнение кода и анализ результата; авторы сообщают заметные различия успеха между задачами и проблемы долгосрочного планирования. **Наше решение:** проверять завершённую траекторию и артефакты на разных задачах, отдельно считать ошибки исполнения и качество модели. **Граница переноса:** набор включает иные семейства задач и модели; его результаты не доказывают перенос на наши private-задачи, выполнение CPU-лимита или отсутствие предобучающего загрязнения. Сами datasets не скачиваем.

### RSRC-003 — DS-Agent

**Источник:** Guo et al., [DS-Agent: Automated Data Science by Empowering Large Language Models with Case-Based Reasoning](https://arxiv.org/abs/2402.17453v5). Идентификатор: `arXiv:2402.17453v5`; v1 — 27.02.2024, v5 — 28.05.2024. Проверен 20.10.2026: метаданные и abstract.

**Факт источника:** case-based reasoning связывает поиск/адаптацию решений с обратной связью; авторы различают исследовательскую и упрощённую deployment-стадии. **Наше решение:** хранить собственные выполненные попытки и причины keep/revert в пределах текущего разрешённого запуска, а повторное использование памяти сравнивать отдельной абляцией. **Граница переноса:** описанное использование экспертного материала Kaggle не является разрешением импортировать чужие решения, внешние тренировочные данные или переносить модели между private-запусками AegML. Результаты и расходы статьи относятся к её постановке.

### RSRC-004 — AIDE

**Источник:** Jiang et al., [AIDE: AI-Driven Exploration in the Space of Code](https://arxiv.org/abs/2502.13138v1). Идентификатор: `arXiv:2502.13138v1`, 18.02.2025; [авторский репозиторий WecoAI/aideml](https://github.com/WecoAI/aideml). Проверены 20.10.2026: метаданные/abstract и происхождение репозитория.

**Факт источника:** ML engineering формулируется как оптимизация кода с поиском по дереву потенциальных решений и повторным развитием перспективных вариантов. **Наше решение:** разделить draft/debug/improve, хранить parent candidate и лучший допустимый checkpoint; глубину и число ветвей ограничивать общим deadline. **Граница переноса:** это мотивация проверяемого search-дизайна, а не доказательство, что дерево лучше простого цикла при 8 CPU и трёх часах. Собственный evaluator не должен доверять числу, напечатанному кандидатом. Репозиторий не устанавливался и не включается автоматически в ZIP.

### RSRC-005 — MLE-bench

**Источник:** Chan et al., [MLE-bench: Evaluating Machine Learning Agents on Machine Learning Engineering](https://arxiv.org/abs/2410.07095v6). Идентификатор: `arXiv:2410.07095v6`; v1 — 09.10.2024, v6 — 26.02.2025; [авторский код оценки](https://github.com/openai/mle-bench). Проверены 20.10.2026: метаданные/abstract и README репозитория.

**Факт источника:** benchmark оценивает end-to-end ML engineering на соревнованиях; работа отдельно рассматривает ресурсное масштабирование и влияние contamination. **Наше решение:** фиксировать задачу, агентный scaffold, модель, seed, budget и grading отдельно; сравнивать завершённый результат и все отказы, а не один удачный текстовый ответ. **Граница переноса:** Kaggle-медаль, baseline и бюджеты MLE-bench не являются банковскими B или public score. Корпус соревнований не переносится в обучение AegML; состояние живого leaderboard и численные результаты не используются как доказательство нашего качества.

### RSRC-006 — Agent Laboratory

**Источник:** Schmidgall et al., [Agent Laboratory: Using LLM Agents as Research Assistants](https://arxiv.org/abs/2501.04227v2). Идентификатор: `arXiv:2501.04227v2`; v1 — 08.01.2025, v2 — 17.06.2025. Проверен 20.10.2026: метаданные и abstract.

**Факт источника:** framework разделяет обзор, эксперименты и отчёт, сохраняет исследовательский код/отчёт и допускает человеческую обратную связь между стадиями. **Наше решение:** отделять исследователя, исполнителя и проверку доказательств; итоговый отчёт строить по реально сохранённым артефактам. **Граница переноса:** роль человека в описанной системе нельзя незаметно добавить внутрь автономного конкурсного запуска. Заявления авторов о качестве/стоимости не подтверждают преимущество нескольких контекстов нашей Qwen или корректность нового evaluator.

## Harness и надёжность инструментальных действий

### RSRC-007 — τ-bench

**Источник:** Yao, Shinn, Razavi, Narasimhan, [τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains](https://arxiv.org/abs/2406.12045v1). Идентификатор: `arXiv:2406.12045v1`, 17.06.2024. Проверен 20.10.2026: метаданные и abstract.

**Факт источника:** оценка сопоставляет конечное состояние среды с целевым и отдельно рассматривает согласованность поведения между повторами через `pass^k`. **Наше решение:** проверять наблюдаемые постусловия каждого mutating tool, учитывать повторы/сбои и долю полностью успешных траекторий; «один вызов сработал» не заменяет надёжность. **Граница переноса:** conversational API-домены статьи отличаются от ML-поиска. Численное `pass^k` нельзя переносить на наш harness или смешивать с `pass@k`; метрики повторяемости сначала получают явное определение и протокол.

### RSRC-008 — SWE-agent

**Источник:** Yang et al., [SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering](https://arxiv.org/abs/2405.15793v3). Идентификатор: `arXiv:2405.15793v3`; v1 — 06.05.2024, v3 — 11.11.2024. Проверен 20.10.2026: метаданные и abstract.

**Факт источника:** авторы исследуют влияние agent-computer interface на работу агента с файлами, кодом и тестами. **Наше решение:** делать инструменты небольшими, результаты — структурированными и ограниченными по размеру, а ошибки — пригодными для исправления; интерфейс harness сравнивать отдельно от выбора модели. **Граница переноса:** исправление software issues не эквивалентно улучшению RMSE/Macro F1. Дизайн интерфейса не является sandbox и не подтверждает безопасность исполнения произвольного Python.

### RSRC-009 — Qwen Function Calling

**Источник:** Qwen Team, [Function Calling](https://qwen.readthedocs.io/en/latest/framework/function_call.html). Идентификатор: официальный документ `framework/function_call`, ветка `latest`; проверены 20.10.2026 разделы protocol, tools/results, templates и limitations. Дата конкретной редакции/commit страницы не зафиксирована.

**Факт источника:** модель предлагает инструмент и аргументы, приложение исполняет действие и возвращает результат. Документ описывает JSON Schema и предупреждает, что генерация не гарантирует соблюдение протокола. Для reasoning Qwen3 отдельно отмечен риск stopword-based ReAct templates. **Наше решение:** проверять capability конкретного endpoint, валидировать имя/schema/ID/state, исполнять разрешённый tool ровно по принятому действию и возвращать соответствующий result; reasoning и final/tool output не смешивать. **Граница переноса:** это документация семейства Qwen3, не доказательство поведения выданного `Qwen3.8-27B` alias, server parser, контекста или авторизации. Не копируем template/server flags без live-проверки; команды установки из страницы не выполнялись.

### RSRC-010 — Qwen-Agent: официальный reference implementation

**Источник:** Qwen Team, [QwenLM/Qwen-Agent](https://github.com/QwenLM/Qwen-Agent). Идентификатор: авторский репозиторий, README default branch на 20.10.2026; commit этого web-среза не закреплён. Проверены README, структура LLM/Tools/Agents и замечания о templates.

**Факт источника:** framework разделяет инструменты, LLM-адаптер и агента; выбор parser/template различается по модели/серверу. README отдельно предупреждает, что Python executor демонстрационного Qwen2.5-Math примера не является sandbox. **Наше решение:** использовать разделение контрактов как reference для собственного лёгкого dispatcher; состояние протокола и права исполнителя проверять независимо. **Граница переноса:** Qwen-Agent не указан в нашем SRC-REQ и не становится разрешённой runtime-зависимостью из-за этой ссылки. До любого заимствования фиксируются версия/лицензия/совместимость; демонстрационный executor не служит доказательством нашей OS-границы.

## Валидация, точная метрика и проверяемое ПО

### RSRC-011 — sklearn: leakage и Pipeline

**Источник:** scikit-learn developers, [Common pitfalls and recommended practices, 1.5.2](https://scikit-learn.org/1.5/common_pitfalls.html#data-leakage). Идентификатор: versioned docs `1.5.2/common_pitfalls`, раздел 10.2; проверен 20.10.2026.

**Факт источника:** preprocessing/feature selection обучаются на train-части; включение test в fit даёт оптимистичную оценку, а Pipeline помогает соблюдать границы. **Наше решение:** строить split до fit, хранить fold-local transforms и проверять, что изменение validation/test не меняет train-fitted состояние. **Граница переноса:** Pipeline не мешает человеку повторно подбирать решение по раскрытому outer holdout и не ограничивает OS-права worker. Термин `test` в документации переводится в соответствующий независимый уровень нашего вложенного протокола, а не только в файл `test.csv`.

### RSRC-012 — sklearn: nested model selection

**Источник:** scikit-learn developers, [Nested versus non-nested cross-validation, 1.5.2](https://scikit-learn.org/1.5/auto_examples/model_selection/plot_nested_cross_validation_iris.html). Идентификатор: versioned example `plot_nested_cross_validation_iris`; проверен 20.10.2026.

**Факт источника:** использование одних данных для выбора параметров и оценки способно сделать оценку оптимистичной; nested protocol разделяет эти роли. **Наше решение:** отделить inner-подбор от замороженного outer-сравнения; регистрировать раскрытие outer и не возвращать его результаты в следующую гипотезу. **Граница переноса:** пример на Iris не подтверждает iid, независимость строк или подходящий split наших зданий/сетевых потоков. После адаптивного просмотра outer он не становится «новым независимым» от одного переименования файла.

### RSRC-013 — sklearn: TimeSeriesSplit

**Источник:** scikit-learn developers, [TimeSeriesSplit, 1.5.2](https://scikit-learn.org/1.5/modules/generated/sklearn.model_selection.TimeSeriesSplit.html). Идентификатор: `sklearn.model_selection.TimeSeriesSplit`, параметры `test_size/max_train_size/gap`; проверен 20.10.2026.

**Факт источника:** API формирует упорядоченные train/test indices и расширяющиеся обучающие части; случайное перемешивание не соответствует этой схеме. **Наше решение:** проверять направление времени и явные period boundaries для Year_Factor. **Граница переноса:** готовый row-based splitter не доказывает корректность наших групп лет. Из-за разного числа зданий в периодах нельзя автоматически считать дефолтные границы по числу строк равными границам Year_Factor; конкретные split задаются и проверяются по MATH.6.

### RSRC-014 — sklearn: F1 label policy

**Источник:** scikit-learn developers, [f1_score, 1.5.2](https://scikit-learn.org/1.5/modules/generated/sklearn.metrics.f1_score.html). Идентификатор: `sklearn.metrics.f1_score`, включая `labels/average/zero_division`; проверен 20.10.2026.

**Факт источника:** при `labels=None` используются метки из y_true/y_pred; `macro` усредняет по классам без весов support; явно добавленные отсутствующие labels и `zero_division` меняют результат. **Наше решение:** основной `macro_f1_task` воспроизводит task-вызов, а `macro_f1_fixed10` остаётся отдельно названной диагностикой по MATH.4. Вручную заданные fixtures проверяют различие политик. **Граница переноса:** документация библиотеки не доказывает параметры скрытого evaluator банка. Нельзя выдавать fixed10, исключение NaN или положительный класс по умолчанию за подтверждённое правило private.

### RSRC-015 — Python unittest

**Источник:** Python Software Foundation, [unittest — Unit testing framework, ветка 3.12](https://docs.python.org/3.12/library/unittest.html). Идентификатор: stdlib `unittest`, fixtures/assertions/subTest/result states; проверен 20.10.2026. Сайт при чтении отображал документацию 3.12.15; наша локальная 3.12.3 не менялась.

**Факт источника:** framework поддерживает отдельные assertions, setup/cleanup, subtests и различает success/failure/error/skip. **Наше решение:** каждой отрицательной/положительной фикстуре дать проверяемое постусловие, сохранять failed/skipped отдельно и не закрывать соответствующий сценарий другим успешным тестом. **Граница переноса:** наличие тестового framework или зелёный unit-test не доказывают точный Docker image, OS-containment, качество ML или перенос на private; фактическая приёмка остаётся привязанной к source/ZIP/environment и конкретному сценарию.

## Как пользоваться реестром при проектировании

1. Для каждого заимствованного решения записывать RSRC-ID, конкретную проверенную версию, собственную адаптацию и сценарий, который может опровергнуть полезность решения.
2. Библиотечные `latest`/default-branch ссылки перед кодированием перепроверять и закреплять, если от них зависит поведение. Наличие первичного источника не закрывает compatibility/live/security HOLD.
3. Сравнивать фиксированный pipeline, AutoML, одноразовый LLM-план, feedback-agent и необязательные роли по общему протоколу из исследовательского и математического документов. Все результаты, ошибки и ограничения должны оставаться видимыми.
4. Не выполнять команды из статей/README автоматически и не получать внешние данные соревнований. По правилам AegML обучение использует только предоставленные материалы; API и code executor проходят отдельные будущие проверки.

Результат этой работы — реестр проверенных первичных ссылок и границ проектных выводов. Новые ML-метрики, преимущество harness, успешный live Qwen, runtime/security PASS или готовность конкурсного агента здесь не заявлены.

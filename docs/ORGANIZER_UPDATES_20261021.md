## 12:57 — пути входных файлов

Организаторы объяснили нулевой результат одной команды: код искал train.csv в корне, хотя task.md указывал regression/participants/train.csv и multiclass/participants/train.csv. Рекомендация — получать пути из условия, без фиксации структуры конкретной публичной задачи.

**Следствие:** плоский ZIP решения не означает плоскую структуру данных задачи. Корневые .py/requirements относятся к переносу нашего кода; input CSV могут находиться во вложенных каталогах, объявленных в task.md. Output submission.csv остаётся рядом с task.md.

**Наша реализация:** H03 resolver сначала разрешает объявленные task-пути. Canonical root fallback сохранён для фактически выданной плоской локальной выгрузки; он не подменяет существующий объявленный путь. Алгоритм ML не ветвится по имени public dataset/target. Первые H04 WSL quality checks использовали плоскую локальную выгрузку. Для H04 Docker-repeat добавлен отдельный запрос на фактическую вложенную раскладку из task.md; до terminal эта проверка имеет статус IN_PROGRESS, не PASS.

Источник: **SRC-CHAT-PATHS-20261021-1257**. Условие закрытия layout-проверки: буквальный python3 solution.py task.md проходит обе задачи с CSV только по объявленным вложенным путям, task/output в корне; provenance подтверждает declared-path selection и одинаковые исходные SHA.

## 13:02 — обращения к Qwen без итогового CSV

По сообщению организаторов, у другой команды обращения к LLM шли, но ошибка эксперимента или некорректный ответ Qwen прерывали процесс до сохранения предсказаний. Платформа не получила файл для расчёта метрики. Указанные7часов не доказывают7часов полезного исполнения кода: очередь/время отображения и реальный лимит процесса — разные сведения.

**Следствие:** успешный LLM-запрос не подтверждает готовность submission. Доверенный baseline должен дать полный валидный CSV до рискованных экспериментов. Отказ кандидата/LLM не должен повреждать этот файл. Некорректное сообщение, timeout и crash требуют явного результата действия и ограниченного восстановления, без ложных api_verified/research_completed.

**Наша реализация:** H04 публикует validated mean/majority CSV до preprocessing и CatBoost fit. Tiny-tests подтвердили сохранность его SHA/mtime при fake-fit/predict failure; CLI сохраняет правдивые флаги этапов и nonzero для ошибки H04. Это ещё не финальная политика восстановления agent/controller. H05.3/H06 должны отдельно проверить обработку recoverable candidate/API errors и завершение с пригодным baseline, без утверждения, что Qwen/AutoResearch успешно отработали. Конкурсный API на H04 не использовался.

Источник: **SRC-CHAT-ERROR-20261021-1302**. Условие будущей приёмки: malformed reply/ошибка эксперимента/timeout после baseline оставляют полный CSV и позволяют контроллеру завершить согласованным degraded-результатом; отдельные строгие API probes при этом сохраняют отказ, а не маскируют его наличием CSV.

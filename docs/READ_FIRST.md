# Что читать и как поручать работу

Мы готовим полноценный автономный ML-агент для новых задач. Текущий итог — полное ТЗ, обзор первичных источников и план исследований. Модели полного агента ещё не обучались. Mini завершила техническую роль и не является готовым конкурсным решением.

## Начать с трёх файлов

1. [PROJECT_STATE.md](../PROJECT_STATE.md) — коротко: цель, факты, ограничения и ближайший шаг.
2. [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md) — нормативное ТЗ: F01–F05, данные/метрики, architecture, качество, безопасность, этапы и все основные проверки.
3. [WORK_BLOCKS.md](WORK_BLOCKS.md) —50 малых подпунктов: что прочитать, зависимости, какие будущиефайлы создать, что проверить и где остановиться.

Читать всё заново перед каждым маленьким изменением не нужно. После этих трёх выбери относящуюся дорожку:

| Для чего | Читать | Когда |
| --- | --- | --- |
| AutoResearch/сравнение подходов | [AUTOML_RESEARCH_BRIEF](AUTOML_RESEARCH_BRIEF.md) → [RESEARCH_PROTOCOL](RESEARCH_PROTOCOL.md) | H01/H07/H09 |
| Qwen harness/роли/память/tools | [QWEN_HARNESS_DESIGN](QWEN_HARNESS_DESIGN.md) | H01.2/H06/H07 |
| Метрики, split, утечки, качество | [MATHEMATICS_AND_VALIDATION](MATHEMATICS_AND_VALIDATION.md) | H01.4/H03/H04/H09/H11 |
| Модули/структуры/вход/выход | [BACKEND_CONTRACT](BACKEND_CONTRACT.md) | H02–H08 |
| Таймер, worker и отказы | [RUNTIME_AND_FAILURES](RUNTIME_AND_FAILURES.md) | H05–H07/H10 |
| WSL/Docker/пакеты/ресурсы | [LOCAL_ENVIRONMENT](LOCAL_ENVIRONMENT.md) | H02.1/H02.4/H10 |
| Что реально доказано | [EVIDENCE_REGISTER](EVIDENCE_REGISTER.md) | При оценке статуса и после каждого блока |
| Первичные статьи и ограничения переноса | [RESEARCH_SOURCES](RESEARCH_SOURCES.md) | Когда обосновываем решение |
| Нерешённые сведения организаторов | [ORGANIZER_QUESTIONS](ORGANIZER_QUESTIONS.md) | Перед API/образом/сабмитом |

Исходные task.md в папках «Регрессия» и «Многоклассовая классификация» описывают публичные задачи; они обязательны для работ с данными. Наше ТЗ описывает агента, который такие задачи решает, и не заменяет исходники. SOURCE_MANIFEST/INDEX/DOC_REVIEW_RECEIPT нужны для версий и SHA, не для ежедневного чтения целиком.

## Ближайшая последовательность

Обзор источников и проектирование находятся в H00/H01. После этой редакции следующий кодовый шаг по команде — **H02.1**, минимальные разрешённые пакеты в уже созданной WSL. Затем entrypoint/TaskContract → метрики/split/CSV → baseline обеих задач → worker и Qwen → настоящий AutoResearch → перенос → сравнение/ZIP/платформа.

Без ключа можно делать offline протокол. После получения ключа H06.2 отдельно проверяет безопасный tool call, без generated code. Для исполнения LLM-кода сначала обязательна H05.1. Ключ ожидается, но пока API_WAIT_LOCAL; условный вывод из platform mini не заменяет локальныенастройки.

## Как давать небольшое задание

> Выполни H03.3 по WORK_BLOCKS и главному ТЗ. Сначала прочитай состояние, исходные task и указанные документы. Реализуй только метрики и разбиения, проверь ручные случаи, сохрани команды/результаты/SHA и ограничения. Обнови состояние/NEXT/INDEX. Следующий подпункт автоматически не начинай.

Каждая задача заканчивается различением: что написано; что реально запущено; что доказано; что ещё NOT_RUN/HOLD. Письменныйобзор, аналитическаяформула, replay, liveAPI, MLfit иофициальный score — разные виды результата.

## Слова простым языком

| Термин | Значение |
| --- | --- |
| Harness | Управляющий слой вокруг Qwen: контракты, инструменты, контекст, исполнение и проверка |
| AutoResearch | Гипотеза → код → эксперимент → измерение → решение → следующая гипотеза |
| Универсальность/переносимость | Один код понимает новые задачи/схемы/метрики и запускается в нужной среде |
| T_fit / inner_score | Данные обучения кандидата / контроль выбора кандидатов внутри разработки |
| Outer | Отдельный контроль замороженного метода, не обратнаясвязь исследования |
| Frozen refit | После фиксации рецепта заново обучить его на всём development без нового поиска |
| Worker / evaluator | Ограниченный исполнитель кандидата / проверенный независимый расчёт метрики |
| Incumbent / best-ready | Лучшая измеренная гипотеза / вариант с уже проверенным пригодным CSV |
| PASS / NOT_RUN / HOLD | Пройдено в указанном scope / не выполнялось / есть незакрытоеусловие |

Начинать дополнительные mini-посылки ради того же наблюдения не нужно. Следующая содержательная работа — полный проект по этому маршруту, с измеренным качеством и честнойприёмкой.

## Быстрый запуск

Нужен Python 3.11+. В рабочем пакете нет сторонних зависимостей; установка использует setuptools как инструмент сборки.

```powershell
git clone https://github.com/osirust/AegMLAI-agent.git
cd AegMLAI-agent
python -m venv .venv
# Windows PowerShell; активация окружения не нужна:
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m aegml run --task examples/task.json --data examples/demo.csv --output-dir runs
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На Linux/macOS вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`. После установки доступна также команда `aegml` внутри окружения. CSV необязателен: уберите `--data`, чтобы подготовить план только по описанию.

`examples/demo.csv` — синтетический пример из четырёх строк, не данные организаторов. Вход `examples/task.json`:

```json
{
  "task_id": "demo-before-case",
  "goal": "Подготовить план после получения официального задания",
  "task_type": "unknown",
  "target_column": null,
  "metric": null,
  "seed": 42
}
```

`task_type`: `unknown`, `classification`, `regression`. Это временный контракт для табличного сценария; после ТЗ он может измениться. Пока тип задачи или метрика неизвестны, оставляйте их неопределёнными. CSV: UTF-8 (BOM допустим), разделитель запятая, уникальный непустой заголовок, хотя бы одна запись, до 20 MiB. Профиль считает записи и пустые/пробельные ячейки; значения `NA`/`null`, дубли и утечки целевой переменной автоматически не определяются.

## Что сохраняется

Команда выводит JSON со `status` и абсолютным `run_dir`. Каждый запуск создаёт новый каталог в `runs/`:

| Файл | Содержание |
| --- | --- |
| `task.json` | Проверенное описание задачи |
| `profile.json` | Число записей, колонки и пропуски; `null`, если CSV не задан |
| `request.json` | Точные system/user сообщения, переданные провайдеру |
| `plan.json` | План: `summary`, `steps`, `assumptions`, `questions` |
| `events.jsonl` | Этапы выполнения с UTC временем |
| `run.json` | Статус, версия схемы/пакета/Python, seed, настройки без ключа, SHA-256 исходных входов, исходников и артефактов успешного запуска |

Ошибка транспорта или неверная схема ответа сохраняет `status=failed` и возвращает ненулевой код выхода. Ошибки входов отклоняются до создания запуска. Ошибки диска могут помешать записи артефактов. Повторный запуск не меняет предыдущий каталог. `completed` означает завершённое построение плана; `executed_training=false` сохраняется явно. Seed записывается для будущих ML-экспериментов, не передаётся как параметр LLM и не гарантирует повторяемость её ответа.

## Демонстрационный адаптер API — историческая основа

Общий адаптер рассчитан на `POST <AEGML_BASE_URL>/chat/completions`, поля `model/messages/max_tokens`, текст в `choices[0].message.content`. Совместимость конкретного сервера и выбранной модели нужно проверить отдельно. Другой протокол потребует отдельного адаптера.

Пример для **уже запущенного локального сервера Ollama**:

```powershell
$env:AEGML_PROVIDER = "chat_completions"
$env:AEGML_BASE_URL = "http://localhost:11434/v1"
$env:AEGML_MODEL = "ИМЯ_УЖЕ_УСТАНОВЛЕННОЙ_МОДЕЛИ"
$env:AEGML_API_KEY = ""
.\.venv\Scripts\python.exe -m aegml run --task examples/task.json --data examples/demo.csv
```

Для удалённого совместимого API задайте его HTTPS `AEGML_BASE_URL`, поддерживаемый идентификатор `AEGML_MODEL` и ключ в `AEGML_API_KEY`. Для vLLM с совместимым сервером можно указать `http://localhost:8000/v1`. Выбор и загрузка весов, GPU-память и установка inference-сервера — отдельная работа после уточнения ресурсов и правил.

При выборе `chat_completions` сервер получает описание задачи и профиль с названиями колонок и количеством пропусков. Строки CSV не отправляются; ключ используется только в заголовке авторизации. Эти метаданные и план сохраняются локально, поэтому содержимое `runs/` тоже следует проверять перед публикацией. Ключи, закрытые данные и веса исключены из Git через `.gitignore`.

Ответ модели должен быть JSON без Markdown. Неверный ответ завершается ошибкой: автоматического исправления и повторных платных запросов нет. Один вызов, сетевой таймаут по умолчанию 60 секунд (`AEGML_TIMEOUT_SECONDS`, максимум 300), лимит ответа 1 MiB, бюджет ответа 1200 токенов (`AEGML_MAX_TOKENS`, максимум 8192). Таймаут не является общим лимитом длительности запуска. Redirect запрещён; HTTP доступен только на loopback, удалённые адреса требуют HTTPS.

Все настройки — переменные окружения. `.env.example` — образец; файл `.env` автоматически не загружается. Чтобы вернуться к демонстрации, задайте `$env:AEGML_PROVIDER = "mock"`.

Протокол локальных серверов: [Ollama compatibility](https://docs.ollama.com/api/openai-compatibility), [vLLM compatible server](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/). Вызовы настоящих моделей в подготовке основы не проверялись.

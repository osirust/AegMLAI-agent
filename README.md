# AegMLAI-agent

Проект полноценного автономного ML-агента для трека Альфа-Будущее 2026: новое условие и данные → контракт и валидация → обучение → Qwen AutoResearch → проверенный submission.csv. Приоритеты — исследовательский цикл, универсальность/переносимость, измеренное качество и ответ в ресурсах платформы.

**Сейчас готовы документы:** полное ТЗ, обзор первичных источников, математика и план будущего исследования. Модели полного агента ещё не обучались; замеры RMSE/F1, A–E и реальный AutoResearch не выполнялись. Mini остаётся историей технической проверки.

## Что действительно реализовано

- Прежний `src/aegml` — демонстрационный JSON-планировщик. Его 21 тест и старый CI не подтверждают обучение конкурсной модели.
- `testmini/` — stdlib-пробник. Для strict v3 локально пройдены 6 файловых сценариев с явным off и 17HTTP-stub сценариев. На рабочих копиях public созданы непустые CSV с 22449/41166 строками, но это mean/majority без признаков.
- Владелец показал strict-посылку с 0 баллов и меткой «Лучшее решение».3,2 секунды — длительность загрузки. Успех API/CSV условно следует из normal exit0 в default required; фактические exitcode/env/диагностика платформы не получены.
- Отдельная WSL на E:,Python3.12.3 и stdlib-venv созданы. ML-пакеты, проектный Docker и проверенная OS-граница пока не готовы. Ключ для локальной разработки ожидается.

Точная область каждого доказательства — [EVIDENCE_REGISTER](docs/EVIDENCE_REGISTER.md). [Mini-инструкция](testmini/README.md) сохранена как история M00 и не является текущим планом полного агента.

## Следующий шаг

После завершения этой редакции по команде H02.1 готовим нужные разрешённые пакеты в существующей WSL. Далее entrypoint/TaskContract → метрики/split/CSV → настоящие модели обеих задач → worker/Qwen → AutoResearch → перенос и чистый ZIP. Безопасный tool call H06.2 возможен по получении ключа; generated code требует предварительной H05.1. Вся цепочка автоматически не запускается.

Целевая структура — root `solution.py` и `agent_runtime/`, описанные в backend-контракте и ещё не реализованные. На платформе Python3.12,8CPU/32GB и до 3 часов на отдельную задачу; тот же код запускают на двух неизвестных private-задачах. Официальные B и private-метрики не опубликованы в полученных материалах.

Репозиторий ранее переведён в private. Исходные данные, ключи, venv, веса, runs и dist в Git не включаются. В этом чате создаётся версия Владимира/Codex; четыре участника сначала готовят независимые версии. AEGYX — отдельный проект на паузе, его окружение не меняется.
